## 1. 产品定位

### 1.1 一句话描述

> 把一段文字创意，变成可直接投喂给「即梦 / 可灵 / Runway」的分镜提示词包，并导出剪映草稿。

### 1.2 要解决的问题

短视频与短剧创作者的核心瓶颈不在"生成画面"，而在**从想法到可执行镜头清单**这一段：

| 现状 | 问题 |
|---|---|
| 直接文生视频 | 没有镜头结构，长片无法控制节奏，返工成本极高 |
| 传统分镜表（Excel/Word） | 有结构但不懂 AI，写出来的描述模型无法理解 |
| 多模型并用 | 即梦要中文自然语言、Runway 要结构化英文，手工翻译两遍 |

ReCut Agent 站在这三者之间：**输出结构化、跨模型、可校验的分镜数据**。

### 1.3 明确不做（范围边界）

- ❌ 不生成图片 / 视频本身（交给即梦、可灵、Runway）
- ❌ 不做时间轴剪辑（只导出剪映草稿，由剪映完成）
- ❌ 不做多人协作 / 团队权限（当前为单用户模型）
- ❌ 不做角色形象设计（角色以文字锚点 + 标签描述）

## 2. 目标用户

| 类型 | 特征 | 核心诉求 |
|---|---|---|
| **主用户**：独立创作者 | 1–3 人小团队，做二创 / 短剧 / 广告 | 从梗概快速产出可执行分镜，控制角色一致性 |
| 次要用户：导演 / 编剧 | 有剧本但不懂 AI 提示词 | 把文字转成模型能懂的语言 |
| 观察用户：学习者 | 想学镜头语言 | 通过计划面板理解景别/焦段/运镜的搭配 |

### 典型场景

- 黑神话类游戏二创：固定角色「天命人」，需要跨 6–12 个镜头保持一致
- 短剧试拍：先出分镜给制片看，再决定是否实拍
- 广告分镜：客户改需求时能快速重排镜头

## 3. 核心用户旅程

```
[1] 写剧情梗概          左栏文本框，20–500 字
        ↓
[2] 选二创风格          搞笑反转 / 燃向踩点 / 黑深残 / 日常整活
        ↓
[3] 选项目角色          从角色资产库勾选 → 锚点自动派生
        ↓
[4] 生成镜头计划        模型输出「几镜 / 每镜时长 / 景别 / 焦段 / 运镜 / 叙事功能」
        ↓
[5] 人工调整计划        改时长、删镜、加镜（此阶段不消耗提示词 token）
        ↓
[6] 确认并展开          并发逐镜生成完整卡片（替换或追加，替换有二次确认）
        ↓
[7] 逐镜微调            对话框对比「改前 / 改后」，确认后采用
        ↓
[8] 补参考首帧          每镜上传首帧图，导出时进 materials/
        ↓
[9] 导出                Markdown / CSV 直接下载；剪映草稿打包 zip
```

## 5. 非功能需求

| 维度 | 要求 | 当前实现 |
|---|---|---|
| 接口响应 | 本地 P95 < 300ms（不含模型调用） | SQLite 单机，实测远低于此 |
| 模型调用 | 超时 90s，失败降级为明确错误 | `LLM_TIMEOUT`，503/502 区分"未配置"与"调用失败" |
| 数据安全 | 密码不可逆、会话可吊销、跨用户隔离 | scrypt + 不透明 token + 所有查询带 `user_id` |
| 请求防护 | 状态变更校验 Origin | `deps.verify_origin` |
| 上传安全 | 类型白名单 + 大小限制 + 内容嗅探 | 5MB，PNG/JPEG/WEBP，解析头部取宽高 |
| 数据容量 | 单项目故事板 ≤ 512KB | 超限返回 413 |
| 部署形态 | 单容器 + SQLite | 未容器化；**单实例限制**（多 worker 会有写锁问题） |
| 响应式 | 1440 主设计，<1150 收窄，<720 隐藏侧栏 | 已实现断点 |
| 测试 | 后端单元/接口测试 | **59 项通过**；前端无自动化测试，靠类型检查 + 截图验证 |

## 6. 数据模型

SQLite 单文件 `backend/recut.db`，WAL 模式，标准库 `sqlite3` 直连（无 ORM）。

| 表 | 关键字段 | 约束 / 说明 |
|---|---|---|
| `users` | id, email, password_hash, status, assets_seeded_at | email 唯一；status ∈ active/disabled |
| `sessions` | token_hash, user_id, expires_at, remember | 存 SHA-256，支持滑动续期 |
| `login_attempts` | email, success, created_at | 用于失败锁定 |
| `projects` | id, user_id, name, storyboard(JSON TEXT), version | storyboard ≤ 512KB；version 为乐观锁 |
| `characters` | id, user_id, name, name_key, role_label, description, consistency, prompt_anchor, tone, version | `UNIQUE(user_id, name_key)`；consistency 预留未用 |
| `tags` | id, user_id, name, name_key, category, tone | `UNIQUE(user_id, name_key)`；category 5 值枚举 |
| `character_tags` | character_id, tag_id | 联合主键，双向级联删除 |
| `uploads` | id, user_id, sha256, mime, bytes, width, height | 二进制存文件系统，`uploads/<sha256>.<ext>` |

### 项目文档（`projects.storyboard`）结构

```jsonc
{
  "idea": "剧情梗概",
  "style": "燃向踩点",
  "model": "即梦 Jimeng",
  "character_ids": [1, 2],        // 项目级角色，锚点由此派生
  "extras": ["cinematic lighting"], // 项目补充词
  "shots": [ /* 故事板卡片数组 */ ],
  "plan": { /* 未完成的镜头计划，可用于续做 */ },
  "anchors": ["..."]              // 旧字段，仅读取兼容
}
```

## 8. 当前状态与已知限制

### 8.1 阻塞项

| 项 | 影响 | 解除方式 |
|---|---|---|
| **未配置模型 Key** | 4 个生成接口全部 503，只能看到演示卡片 | 在 `backend/.env` 填 `LLM_API_KEY`（可选 `VISION_API_KEY`），跑 `python -m scripts.check_models` 自检 |

### 8.2 已知限制（非缺陷，是范围选择）

- **一致性评分未实现**：`characters.consistency` 字段空置；图像级评分需要角色参考图 + 算法服务，已评估过但延后
- **剪映草稿未验证**：本机未安装剪映，导出结构按公开格式编写，可能需要按真实版本微调
- **单实例部署**：SQLite 写锁限制，`uvicorn --workers > 1` 会出问题；上公网多实例需迁移 PostgreSQL
- **逆向解析精度**：等距抽 6 帧，快切素材可能合并镜头（后续可用 PySceneDetect 做真实镜头切分）
- **无前端自动化测试**：依赖 `vue-tsc` + 无头浏览器截图，交互逻辑靠人工验证
- **未公网部署**：目前仅本地 `127.0.0.1`

### 8.3 数据安全相关的设计决策

- 登录锁定按**邮箱**而非 IP：防代理绕过，代价是可被恶意锁号（通过 CLI `unlock` 恢复）
- 会话 token 只存哈希：库泄露也无法直接冒用
- 角色绑定 `character_ids` **只信任前端**：模型返回的同名字段会被丢弃，防止模型改写数据

## 11. 风险与开放问题

| 风险 | 影响 | 应对 |
|---|---|---|
| 模型输出格式不稳定 | 解析失败、卡片缺失 | 已有 `parse_*_payload` 容错 + 单镜重试；后续可加 schema 校验与自动重试 |
| 模型费用不可控 | 成本超预期 | 两阶段设计已把"结构"和"提示词"分开，计划阶段不烧提示词 token |
| 供应商模型下线/改名 | 接口报错 | `scripts/check_models.py` 会列出当前可用模型，改 `.env` 即可，不用改代码 |
| 单人维护 + 无 CI | 回归风险 | 后端 59 项测试；前端建议尽快补 e2e |
| 商用许可 | 未来接入人脸模型时的合规问题 | InsightFace 权重为非商用；若做评分应选 Apache-2.0 的 SFace |
